# R1a - API parity table against glam-rs 0.33.8

Branch `chore/api-parity`. Tooling task, no Cairo library code. Deliverables (the ONLY files you
may create or edit): `scripts/api_parity.py`, `docs/API_PARITY.md` (generated by the script), and
one added line in `scripts/check.sh` running `python3 scripts/api_parity.py --check`.

## Goal

A deterministic, dependency-free Python 3 script that compares the public API of glam-rs 0.33.8
with the Cairo port and writes a parity table, so that the final audit (task R1) and every future
pull request can see exactly what is ported, what is deliberately dropped and what is missing.

## Inputs

- glam-rs 0.33.8 sources: path given with `--glam-rs <dir>` (default `/tmp/glam-rs`; clone with
  `git clone --depth 1 --branch 0.33.8 https://github.com/bitshifter/glam-rs /tmp/glam-rs`).
  Because CI has no clone, the script supports two modes: `--refresh` parses the Rust sources and
  rewrites a committed inventory section inside `docs/API_PARITY.md` (or a small committed data
  file `scripts/api_parity_glam.json`, also allowed); the default and `--check` modes use that
  committed inventory and only parse the Cairo side, so CI never needs the Rust clone.
- Rust side, scalar code paths only: `src/f32/{vec2,vec3,affine2,affine3,mat3}.rs`,
  `src/f32/scalar/{vec4,quat,mat2,mat4}.rs`, `src/bool/bvec{2,3,4}.rs`,
  `src/i32/ivec{2,3,4}.rs`, `src/u32/uvec{2,3,4}.rs`, `src/euler.rs`, `src/f32/float.rs`,
  `src/f32/math.rs`, `src/swizzles/vec_traits.rs`, `src/camera/**`: every `pub fn`, `pub const`
  and operator `impl` (`Add`, `Mul<f32>`, `From<...>`, `Index`...) per type.
- Cairo side: `packages/glam/src/**/*.cairo` and `packages/fixed/src/*.cairo`: trait functions,
  trait consts, module-level `pub fn`, `impl X of CoreTrait<...>` operator/conversion impls.
- Read `docs/DESIGN.md` sections 1 and 3 for the deliberate drops and renames: NaN/infinity items
  (`is_nan`, `is_finite`, `NAN`, `INFINITY`...), SIMD/aligned types, `Mul<f32>` operators replaced
  by `mul_scalar`-style named methods, `From` impls expressed as `Into`, Euler methods living on
  extension traits in `euler.cairo`, deprecated `Mat4::perspective_*`/`orthographic_*` replaced by
  `camera`, `Sum`/`Product`, slices (`from_slice`, `write_to_slice`), `Display`.

## Output: `docs/API_PARITY.md`

Header (glam-rs version, generation command), a summary table per type (`ported / dropped by
design / renamed / missing / extra`, with counts and a percentage), then one section per type
listing every glam-rs item with its status and, for `renamed`/`dropped`, the rule that applies
(rules are data at the top of the script: exact names or regexes with a one-line reason each).
`missing` must contain no false positive that a rule should have explained: review the list and
add rules until what remains is genuinely unported. `extra` lists Cairo-only items (e.g.
`mul_scalar`, `Affine3RigidTrait`). Output is byte-deterministic (sorted), wrapped at 100 columns
where practical.

## Done

`python3 scripts/api_parity.py --check` exits 1 when `docs/API_PARITY.md` is stale; it is wired in
`scripts/check.sh`; `scripts/check.sh` is green in the foreground. Conventional commit
`chore(parity): API parity table against glam-rs 0.33.8` ending with the line
`Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`; push; `gh pr create --base main` (body

committed): how the parser works, its known blind spots, the summary table, the genuinely missing
items grouped by module. Two other tasks are in flight (`affine3`, `fixed::exp`): their modules
are stubs today and will show as missing; that is expected. Work autonomously; do not ask
